## Platform

web

## Users

**Основной пользователь** — человек, который ведёт долгую ролевую переписку с нейросетью:
держит несколько историй одновременно, возвращается к ним неделями, читает и пишет
и с компьютера, и с телефона.

Приложение открывается наружу с **открытой регистрацией**: аккаунт заводит любой
незнакомый человек из интернета. Роли две — `user` и `admin`; первый
зарегистрированный получает `admin`. Администратор видит список пользователей,
меняет роли, удаляет аккаунты и один имеет право смотреть общий журнал отладки.

**Второй вход в тот же продукт** — Telegram. Пользователь привязывает
`telegram_id` к аккаунту и продолжает те же чаты с теми же персонажами и той же
памятью, не открывая браузер.

## Product Purpose

Самостоятельная альтернатива SillyTavern: тонкий веб-клиент и Python-бэкенд,
который берёт на себя всю работу с нейросетями, файлами, звуком, документами и
памятью. Один процесс обслуживает и веб, и Telegram-бота.

Успех — длинная связная история, которую не приходится чинить руками: персонаж
не забывает состояние мира, чат открывается там, где его оставили, а сеть,
которая отвалилась на телефоне, восстанавливается сама.

## Positioning

Четыре свойства, подтверждённые как обязательные к сохранению:

1. **Один бэкенд для веба и Telegram.** Бот работает в том же процессе и той же
   базе. Один персонаж, один чат, одна память — с телефона и с компьютера.
2. **Память Horae.** Гибрид World Info и снимков состояния: модель получает
   состояние мира, а не только последние реплики.
3. **Канвас и документы.** Двухоконный режим, контекстное редактирование
   выделенного фрагмента, история версий, экспорт в Docx/PDF.
4. **Цельность вместо набора плагинов.** Предсказуемое поведение, тесты,
   документация, изменения в CHANGELOG тем же коммитом.

## Operating Context

- Две среды, одна история: браузер (десктоп и телефон) и Telegram.
- Долгие сессии с переключением между чатами, персонажами и групповыми чатами
  с ИИ-режиссёром.
- Мобильная сеть нестабильна: вкладка уходит в фон, телефон засыпает,
  соединение рвётся. Восстановление связи — часть обычного использования,
  а не аварийный случай.
- Провайдеры подключаются через LiteLLM-прокси; расход токенов платный и виден
  в статистике (`usage_days`: запросы, prompt/cached/completion/reasoning).
- Подключение настраивается в интерфейсе (⚙ → «Подключение»). Секреты
  (`ADMIN_PASSWORD`, `ACCESS_CODE`, `TELEGRAM_BOT_TOKEN`) живут в `.env`,
  а не в базе.

## Capabilities and Constraints

**Что приложение умеет.** Карточки персонажей с импортом/экспортом PNG/JSON V2;
чаты со свайпами, правкой, регенерацией, продолжением и ответами на сообщения;
групповые чаты с режиссёром; память Horae; вложения (картинки, аудио с
микрофона, видео, Word/PDF); LaTeX через KaTeX; запасная модель при сбое
основной; канвас; импорт/экспорт чатов (нативный формат и SillyTavern);
аккаунты, друзья, шаринг чатов; три слоя доступа (HTTP Basic Auth · аккаунты ·
код доступа); Telegram-бот.

**Границы, которые работа обязана сохранять.**

- **Фронтенд без сборки.** Vue 3 с CDN, один `app.js`, Node.js не требуется.
  Статику раздаёт сам бэкенд.
- **Интерфейс на русском.** Русский — язык интерфейса и комментариев в коде.
  Это решение, а не задел под локализацию; идентификаторы — английские.
- **Один процесс и SQLite.** Никаких внешних сервисов, очередей и отдельной
  СУБД. Запуск двойным кликом по `start.bat` остаётся возможным.
- **Самостоятельный хостинг.** Свой сервер или Docker. Ничто не должно
  требовать облака, подписки или чужой инфраструктуры.

**Открытые решения — зафиксированы, но не приняты.** Открытая регистрация
сейчас ничем не ограничена, и следующие вопросы к ней ещё не закрыты:

- `/api/auth/register` открыт без приглашения, капчи и подтверждения адреса;
- квот на расход по пользователям нет — `usage_days` считает агрегат по
  (день, модель, вид) без владельца, то есть расход общий;
- ограничения частоты запросов нет;
- восстановления пароля нет: сброс возможен только через администратора;
- модерации содержимого и жалоб нет.

## Product Principles

1. **Одна история, два входа.** Веб и Telegram не расходятся: общий процесс,
   общая база, общая память.
2. **Целостность важнее количества возможностей.** Новое принимается, только
   если не рассыпает существующее.
3. **Данные пользователя принадлежат ему.** Изоляция по владельцу — не намерение,
   а проверяемое поведение с тестами.
4. **Простота запуска — свойство продукта.** Один процесс, SQLite, двойной клик.
5. **Поведение работающей установки меняется осознанно.** Умолчания переезжают
   только для новых, тихая смена настроек у существующих пользователей — нет.

## Accessibility & Inclusion

Целевая планка — **WCAG 2.1 AA**, подтверждена пользователем как обязательная. Это
цель, а не достигнутое состояние: одни критерии держатся, другие провалены.

**Что уже держится.** Контраст 4.5:1 для текста и 3:1 для нетекстовых элементов —
каждое значение посчитано, в обеих темах. Клавиатурная достижимость строк списков
и файловых полей, aria-подписи для иконочных кнопок, ловушка фокуса с возвратом на
прежнее место, вежливый `aria-live` на генерации.

**Что не держится.**

- **1.3.5 Identify Input Purpose.** У полей входа и регистрации нет `autocomplete`:
  менеджер паролей не опознаёт в них логин и пароль.
- **3.3.2 Labels or Instructions.** 23 контрола подписаны только `placeholder`.
  Подпись исчезает с первым нажатием клавиши, и человек, вернувшийся к полю через
  минуту, уже не знает, что в нём.
- **4.1.2 Name, Role, Value.** Полосы вкладок — обычные кнопки с классом `active`:
  ни `role="tablist"`, ни `aria-selected`. Скринридер читает подряд шесть кнопок и
  не сообщает, какая из них открыта.
- **2.4.7 Focus Visible.** Три поля снимают кольцо фокуса (`outline: none`) и не
  дают ничего взамен: правка сообщения, ввод командной палитры, редактор канваса.
- **1.4.3 Contrast (Minimum).** Плейсхолдеры отданы браузеру по умолчанию — 4.10:1
  против требуемых 4.5:1.

Мобильный веб — равноправная среда, а не уступка: адаптив ниже 768px, нижние
шторки вместо боковых панелей, цели нажатия не меньше 44×44.
