# Волна 1: Фундамент и три бага — план реализации

**Цель:** починить три подтверждённых бага и заменить плоскую палитру из 13 цветов
семантической системой токенов, на которую смогут опереться волны 2–4.

**Подход:** три файла, независимые друг от друга изменения. Бэкенд сортирует по активности
и отдаёт группам недостающие поля. Фронтенд перестаёт слать в PATCH поля, которых
пользователь не касался. CSS получает двухслойную систему токенов (семантика поверх
значений) и мигрирует на неё все 229 обращений `var()`.

**Ограничения:** без сборки, без зависимостей, без изменения WebSocket/SSE и реактивности
Vue. Никакого нового API-эндпоинта. Обратная совместимость: старые имена токенов
остаются алиасами.

**Спека:** отчёт «Редизайн TaleEngine», раздел «Порядок работ», волна 1.

## Глобальные ограничения

- Шкала кегля 12–30px, микро-размеров (10px, 11px) в системе не остаётся.
- Нетекстовый контраст (границы, ползунок прокрутки) — не ниже 3:1 (WCAG 1.4.11).
- Текстовый контраст — не ниже 4.5:1 на всех поверхностях, где текст реально появляется.
- Тёмная тема остаётся единственной активной. Светлая только объявляется токенами
  под `[data-theme="light"]`, автопереключения по `prefers-color-scheme` в этой волне нет.
- `git` в репозитории недоступен (dubious ownership), поэтому откат — из копий
  в `C:/Temp/claude/wave1-backup-*`.

## Задача 1: Сортировка списков по последней активности

**Файлы:** `backend/main.py:775-808` (`_session_previews`), `:811-849` (`list_sessions`),

## Задача 2: PATCH метаданных сессии шлёт только изменённое

**Файлы:** `frontend/app.js:2423-2433` (`applySessionMeta`), `:3684`, `:3740`, `:3744`,
`:3750` (места вызова), `:947-970` (`openSession`), `:988`, `:1069`, `:2941`
**Бэкенд:** `backend/main.py:1059-1093` — добавить поля в карточку группы

**Что не так, точно:** группы открываются как `openSession({ id: g.id })`, в объекте нет
метаданных, поэтому `this.authorNote = s.author_note || ""` кладёт пустую строку.
Дальше любое изменение на вкладке «Персона» вызывает `applySessionMeta`, который
безусловно шлёт три поля.

Обработчик делает `payload.model_dump(exclude_none=True)`, поэтому:
- `persona_id: null` сервер **отбрасывает** — персона никогда не стиралась;
- `author_note: ""` и `timezone: ""` — пустые **строки**, они записываются.

Стираются `author_note` и `timezone`. Это же касается ещё семи мест, где
`openSession` вызывается с голым `{ id }`, а не только групп.

- [x] **Шаг 1.** `applySessionMeta(fields)` принимает объект и шлёт ровно его.
      Защита от вызова без аргумента и от передачи Event: если аргумент не простой
      объект — не отправлять ничего.
- [x] **Шаг 2.** Четыре места вызова в шаблоне передают конкретное поле:
      `applySessionMeta({ persona_id: sessionPersonaId })`,
      `applySessionMeta({ timezone: sessionTimezone })`,
      `applySessionMeta({ author_note: authorNote })`.
- [x] **Шаг 3.** `/api/groups` начинает отдавать `author_note`, `persona_id`, `background`,
      чтобы карточка группы была полной.
- [x] **Шаг 4.** `openSession` при получении объекта без метаданных ищет полную запись
      в `this.sessions`, `this.groups`, `this.sharedSessions` по id и берёт значения оттуда.
      Это чинит все восемь мест вызова разом, а не только группы.
- [x] **Шаг 5.** Места вызова с группой передают объект целиком (`openSession(g)`).
- [x] **Шаг 6.** Проверить, что `node --check` проходит и `template:` цел.

## Результат

Все задачи выполнены, проверки пройдены (verify=0, sort=0, node --check=0).

### Два отклонения от плана

**1. Цель «≥1.2 между соседними поверхностями» недостижима в тёмной теме.**
Замер показал потолок 1.08–1.24: чтобы взять 1.2 на каждой паре, верхние слои
пришлось бы осветлить до серого и перестать быть тёмной темой. Намерение выполнено
другим средством: введён `--border-strong` (3.79 к surface-0), который несёт
опознавание контролов, и `--edge-highlight` для кромки. Рекомендация из отчёта в
этой части была неверной, и это исправлено здесь, а не унаследовано.

**2. Найдена и исправлена регрессия, внесённая в этой же волне.**
Первая версия подняла `.drawer` и `.card` на одну ступень `--surface-2`, из-за чего
карточки в панели настроек слились бы с её фоном. Дровер возвращён на `--surface-1`
как постоянная панель (наравне с сайдбаром и композером), а для карточек внутри
модалок добавлено правило `.modal .card` с утопленной поверхностью. Соседние
поверхности теперь не совпадают нигде.

**Поправка к таблице замеров выше:** `--border-strong` в реализации взят как
`#667084` (3.79 / 3.50 / 3.12 на трёх поверхностях), а не `#5c6678` из плана:
последний давал 2.68 на `--surface-2`, то есть не проходил порог 3:1 там, где
поле ввода лежит внутри карточки.

### Чего проверка НЕ покрывает

Визуально проверен только экран входа: войти в приложение я не могу, пароли в поля
не ввожу. Основной экран (лента, сайдбар, дровер, модалки) проверен статически —
разбор CSS браузером, резолв всех токенов, сохранность разметки — но не глазами.
Прогон по экранам после входа остаётся за вами.
