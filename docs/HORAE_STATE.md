# Horae State Engine — состояние сюжета

Перенос плагина [Horae](https://github.com/ceh51453-alt/horae) (SillyTavern,
v1.15.1) на сервер TaleEngine. Дизайн и решения — в
[superpowers/specs/2026-09-26-horae-state-engine-design.md](superpowers/specs/2026-09-26-horae-state-engine-design.md).

Остальные слои памяти (лорбук World Info, мастер-снимок, атомарные факты,
активное окно — [HORAE.md](HORAE.md)) остаются и работают вместе с этим. Каждый
модуль включается отдельно.

## Зачем

В длинной ролевой модель теряет нить: вчерашнее становится «сегодня утром»,
одежда меняется между абзацами, отношения NPC переворачиваются, подаренный
предмет исчезает, выброшенный возвращается. Horae ведёт учёт по структурным
якорям: модель в конце каждого ответа служебными тегами сообщает, что
изменилось, сервер копит состояние и на каждом ходу возвращает его модели
компактным блоком.

## Как это работает

```
ответ модели ─► parse_reply: текст без тегов ─► Message.content
                          └─► мета ответа ─────► Message.horae.metas[свайп]
меты всех ответов + журнал правок ─► replay ─► состояние сюжета
состояние ─► блок «[Снимок текущего состояния …]» в хвост промпта следующего хода
```

1. **Правила тегов** (промпт `system`, ≈3–4 тыс. токенов) стоят в системном
   промпте — это кэшируемое начало запроса. Опция `rules_position: tail`
   переносит их в хвост (сильнее, но по полной цене на каждом ходу).
2. **Модель пишет** в конце ответа:
   ```
   <horae>
   time:2026/2/4 15:00
   location:Таверна·зал
   atmosphere:шумно
   characters:Вольф, Марина
   costume:Вольф=кожаная куртка
   item!:🗝Ключ от подвала|ржавый=Марина@карман фартука
   npc:Вольф|серая шерсть=молчалив@постоянный гость {{user}}~age:35~job:наёмник
   affection:Вольф=40
   agenda:2026/2/4|Марина обещала показать подвал
   </horae>
   <horaeevent>
   event:important|Марина отдала Вольфу ключ от подвала
   </horaeevent>
   ```
3. **Сервер** при сохранении ответа вырезает блоки из текста (в чате и в истории
   их нет — и в Telegram тоже) и кладёт разобранное в мету свайпа. Во время
   стрима интерфейс прячет теги и пишет «🕰 Horae записывает…».
4. **На следующем ходу** в хвост промпта (после мастер-снимка) идёт блок
   состояния, а перед фокусом — короткое напоминание формата.

Режим «вне роли» (OOC) тегов не просит. Канвас их не получает, а случайные
вырезает.

## Поля тегов

| Поле | Когда | Смысл |
|---|---|---|
| `time:` | каждый ход | дата и время сюжета (`2026/2/4 15:00`, фэнтези-календарь, свой календарь) |
| `location:` | каждый ход | место; иерархия через `·` («Таверна·зал») |
| `atmosphere:` | каждый ход | атмосфера сцены |
| `characters:` | каждый ход | присутствующие через запятую |
| `costume:Имя=…` | каждый ход | одежда присутствующих |
| `item:` / `item!:` / `item!!:` | при изменении | `эмодзиИмя(кол-во)\|описание=владелец@место`; `!` важный, `!!` критичный |
| `item-:Имя` | израсходован/утерян | удалить предмет |
| `npc:Имя\|внешность=характер@отношение~поле:значение` | появление/изменение | частичное обновление: `npc:Вольф\|=@друг {{user}}` меняет только отношение |
| `affection:Имя=40` / `Имя+5` | появление/изменение | расположение к пользователю (абсолютное / сдвиг) |
| `agenda:дата\|текст` / `agenda-:ключевые слова` | новое / выполнено | планы, обещания, зацепки |
| `rel:A>B=тип\|примечание` | при изменении | сеть отношений (модуль `send_relationships`) |
| `mood:Имя=состояние` | при изменении | настроение (модуль `send_mood`) |
| `scene_desc:…` | новое место | постоянные черты места (модуль `send_location_memory`) |
| `event:уровень\|текст` | каждый ход | событие хода: `normal` / `important` / `critical` |
| `<horaetable:Имя>r,c:значение</horaetable>` | по правилам таблицы | ячейки своих таблиц |
| `<horaerpg>…</horaerpg>` | RPG | шкалы, статусы, навыки, атрибуты, снаряжение, репутация, уровень, валюта, крепости |

Уровни событий понимаются и по-русски («важное», «ключевое»), и по-английски.
Модель забыла обёртку и написала строки полей голыми в конце ответа — они тоже
разбираются (только хвостовой блок, минимум два поля, одно из них время, место
или событие) и вырезаются.

## Состояние

Состояние не хранится: оно каждый раз пересчитывается (`horae_state.replay`)
из мет ответов по порядку и журнала правок. Поэтому свайп, правка или удаление
ответа меняют его без отдельной «пересборки».

- **Время, место, атмосфера** — последнее непустое. Относительное время
  («вчера», «прошлый вт», «3 мес. назад», «через 2 дн.») считается от текущей
  даты сюжета; понимаются `2026/2/4`, `04.02.2026`, «4 февраля 2026 года»,
  свой календарь («Год 5, 3 Инея»), фэнтези-даты («третий день месяца инея»).
- **Присутствующие** — последний непустой список; костюмы и настроение в блок
  идут только для присутствующих.
- **Предметы** — по базовому имени без количества («Пиво(3 бутылки)» и «Пиво(1
  бутылка)» — один предмет), со сквозными номерами `#001`. Важность только
  растёт. Количество `(0 …)`, пометка «(израсходовано)»/«(уничтожено)» или
  владелец «нет» удаляют предмет. Защищённый 🔒 предмет ИИ не меняет иконку,
  важность и описание.
- **NPC** — номера `N001`, частичные обновления; пол, раса и день рождения
  ИИ не переписывает (только заполняет пустые). Возраст «растёт» с датой
  сюжета (от дня рождения или от даты, когда возраст был записан).
- **Расположение** — абсолютное значение или сдвиг; словесный уровень
  («дружба», «вражда»…) — для интерфейса.
- **Планы** — выполненный пункт `agenda-:` снимает совпадения (по тексту или
  подстроке от 4 символов). Не разрушительно: свайп на вариант без `agenda-`
  вернёт пункт. Удалённый пользователем пункт ИИ повторно не добавит.
- **Отношения, память сцен** — правленное пользователем ИИ не перезаписывает;
  удалённое место ИИ не пересоздаёт.
- **Побочная сцена** (🎭 у сообщения) — ответ не участвует в состоянии,
  хронологии, свёртках, поиске и переносе (сон, флешбэк, мини-театр).

### Правки пользователя

Любая правка во вкладке «Хроника» — запись журнала с якорем: id последнего
сообщения в момент правки. В повторе она встаёт на своё место, поэтому позже
модель может обновить поле снова (как в плагине, где правка писалась в
последнее сообщение), а **«Откатить»** правку — просто удалить запись. Журнал
виден в «Настройках» вкладки.

Переименование NPC переносит имя во всё состояние (расположение, костюмы,
отношения, владельцев предметов и RPG) и запоминает псевдоним: если модель
потом напишет старое имя, оно сведётся к новому. Удалённого NPC модель не
вернёт, пока его не добавят руками.

## Хронология и свёртки

События всех ответов — хронология. В блок состояния идут все ключевые и
важные события, свёртки и последние `context_depth` (15) обычных, с датой и
относительным временем:

```
[Сюжетная линия]
📋 [Сводка·2026/2/1~2026/2/3](3 дня назад): …
★ #812 2026/2/2 10:00(позавчера): Вольф поклялся защищать Марину
○ #820 2026/2/4 10:00(сегодня): Спустились в подвал
```

- **Авто-свёртка** (`summary_enabled`, по умолчанию выкл.). Ответы старше
  последних `summary_keep_recent` (5), не покрытые свёртками, копятся в буфер;
  набралось `summary_buffer_messages` (10) ответов или `summary_buffer_tokens`
  токенов — самый старый пакет (до `summary_batch_messages`/`_tokens`)
  сворачивается служебной моделью в `<horaesummary>` по полному тексту или по
  событиям (`summary_source`).
- **Свёртка свёрток**: набралось `resummary_threshold` (7) свёрток одного
  уровня — они сворачиваются в свёртку уровня выше (до 4 раундов за проверку).
- **Ручное сжатие**: выбрать события/свёртки → «Сжать в свёртку» (по событиям
  или по полному тексту их сообщений).
- **Ручная свёртка**: свой текст на диапазон «#с — #по».
- Свёртку можно **развернуть** (в промпт снова идут исходные события),
  править и удалить (дети возвращаются).
- **Скрытие** (`summary_hides`, вкл.): сообщения, покрытые активной свёрткой,
  активное окно может выбросить из промпта так же, как покрытые мастер-снимком.
  Это `/hide` плагина: мастер-снимок можно выключить и держать длинный чат одной
  хронологией Horae — она дешевле (свёртка пишет абзац, а не весь снимок).

Удаление сообщения внутри свёртки снимает свёртку (её текст пересказывает
удалённое).

## Вспоминание событий

`recall_enabled` (вкл.). Для каждого ответа ИИ хранится документ из его меты
(`HoraeMemoryDoc`): события, «место персонажи дата» и RPG. На ходу ищутся
документы сообщений, которых модель **не видит** дословно (старше окна или
срезанных бюджетом):

1. **Структурный слой** — по намерению реплики и русским ключевым словам
   (`backend/horae_prompts_ru/recall_keywords.json`): «впервые» + имя → первое
   появление; «в прошлый раз» + одежда/настроение; подарки и важные предметы;
   важные события; темы (клятвы, утраты, тайны, сила) — плюс соседние ответы ±3.
2. **Смысловой слой** — косинус векторов, если задана `embedding_model` и
   векторы посчитаны у ≥ 90 % документов (порог `recall_threshold`, растёт с
   числом документов), иначе лексическое сходство (`recall_lexical_threshold`).
3. **Переписывание запроса** (`recall_query_rewrite`, выкл.) — служебная модель
   пишет замысел сцены и до 5 поисковых запросов.

Слияние RRF (k = 60) с бонусом за общих с текущей сценой персонажей;
необязательно — переранжирование моделью rerank (`recall_rerank`). Лучшие
`recall_full_text_count` (3) воспоминания со сходством от
`recall_full_text_threshold` (0,9) идут полным текстом ответа (до
`recall_full_text_chars`). Блок:

```
[Воспоминание — фрагменты из прошлого, связанные с текущей сценой. Только для справки, не часть текущего контекста]
#415 (3 мес. назад 2025/11/2 18:00) | Сцена:Пристань | Кай(плащ) | ●Лея впервые встретила Кая | NPC:Кай(проводник)
```

Нет подходящих — нет и блока.

## Служебные задачи

Идут на `aux_model` (пусто — `summary_model` подключения, затем модель чата),
по одной на процесс и с паузой `aux_delay_ms` (1000 мс) — очередь
«вспомогательного API» плагина.

- **ИИ-анализ ответа** — кнопка у сообщения или фоном после хода
  (`auto_analyze`): `off`; `gaps` (по умолчанию) — только если модель писала
  теги хотя бы в одном из последних 10 ответов и в этом просто забыла; `always`
  — каждый ответ без тегов (+1 запрос на такой ответ). Результат сливается с
  метой.
- **ИИ-скан истории** — ответы без событий (старый или импортированный чат)
  пачками до 80 000 токенов и 20 сообщений; по галочкам — ещё сцена, NPC,
  расположение, отношения. Прогресс, «Остановить», «Отменить скан» (меты — как
  до скана).
- **«✨ Заполнить ИИ»** профиль NPC по последним 20 упоминаниям.
- **Новый чат с памятью** — последние N ответов дословно, всё раньше —
  стартовым состоянием и пересказом (свёртки и непокрытые события), плюс
  (по галочке) документы поиска этого чата и его предков.

## Таблицы

Свои таблицы (строка 0 и столбец 0 — заголовки). Области: **этот чат**,
**персонаж** (шаблон в профиле персонажа, данные — в чате) и **глобальные**
(шаблон для всех чатов, меняет администратор). Модель заполняет их блоком
`<horaetable:Имя>r,c:значение</horaetable>`; заголовок пишет, только если он
пуст; заблокированные строки, столбцы и ячейки не трогает; таблица растёт.
Данные = база + вклады ИИ из ответов после базы; правка ячейки, очистка,
структура, замок или переименование делают текущие данные новой базой (замок
действует на будущие записи, а не задним числом).

## RPG

`rpg_enabled` и модули: шкалы (HP/MP/SP и свои), статусы, навыки, атрибуты
(Сила…Харизма и свои), снаряжение (слоты по расовым шаблонам), репутация,
уровень и опыт, валюта, крепости. «Только пользователь» (`rpg_user_only`) —
модуль ведётся лишь для персоны. Экипированный предмет уходит из инвентаря и
возвращается при снятии. Во вкладке — карточки присутствующих, правки
значений, настройки категорий, валют и слотов, бросок кубиков.

## Настройки

Три уровня: **глобальные** (`/api/horae/settings`, меняет администратор) ←
**профиль персонажа** ← **этот чат**. Значение `null` снимает переопределение
уровня. Полный список ключей — в дизайн-документе §7. Главные:

| Ключ | По умолчанию | Что |
|---|---|---|
| `enabled` | вкл. | слой Horae для чата |
| `parse_tags` / `inject_state` | вкл. | просить и разбирать теги / отдавать блок состояния |
| `rules_position` | `system` | правила тегов в системном промпте или в хвосте |
| `tag_reminder` | вкл. | напоминание формата перед фокусом |
| `auto_analyze` | `gaps` | см. «Служебные задачи» |
| `send_*` | см. ниже | что отдавать модели: хронологию, персонажей, расположение, характер главных, предметы, планы (вкл.); память сцен, отношения, настроение (выкл.) |
| `context_depth` | 15 | сколько последних обычных событий |
| `summary_*`, `resummary_*` | выкл. | авто-свёртка |
| `recall_*` | вкл. | вспоминание |
| `rpg_*` | выкл. | RPG |
| `calendar` | выкл. | свой календарь: месяцы «Название:дней» |
| `prompts` | — | свои промпты по ключам |

Промпты по умолчанию — русские тексты плагина (`backend/horae_prompts_ru/`),
их можно заменить во вкладке «Промпты», сохранить набором и выгрузить. Два
встроенных набора: компактные события (80–150 символов) и расширенные
(150–280, для свёрток и поиска). Подстановки плагина (`{{user}}`, `{{char}}`,
`${sceneDescLine}`, `${systemPromptAddition}`…) работают — свои промпты из
SillyTavern переносятся как есть.

## Импорт и экспорт

- **Импорт чата SillyTavern** переносит данные Horae целиком: `horae_meta`
  каждого ответа и теги в тексте каждого свайпа → меты; `chat[0]` (свёртки с
  переводом индексов в id, память сцен, отношения, планы, таблицы, RPG,
  удалённые NPC и планы) → состояние чата. Раньше всё это сплющивалось в одну
  текстовую запись «Состояние сюжета» — теперь её нет, если структурные данные
  нашлись.
- **Нативный экспорт/импорт** чата несёт меты и состояние Horae.
- **Экспорт данных Horae** (`/horae/export`) и **импорт**: «по id» (в тот же
  чат) или «как стартовое состояние» другого чата.
- **Ветка** чата копирует меты и состояние до развилки.

## Групповые чаты и Telegram

Группа получает правила, блок состояния и напоминание для каждого отвечающего;
теги каждого ответа разбираются. Вспоминание в группе ищет только перенесённые
из прошлого чата воспоминания: транскрипт группы идёт целиком.
Telegram-бот работает с тем же состоянием; теги в Telegram не уходят,
фоновая обработка — после отправки ответа.

## Что исправлено против плагина

- Пакетный скан с русскими промптами: ответ резался по `===消息#N===`, а
  модель писала `===сообщение#N===` — каждый пакет кончался ошибкой.
- Промпт сжатия: маркер русского раздела не совпадал, модель получала обе
  инструкции разом.
- Количество с кириллицей («Пиво(3 бутылки)») давало дубль предмета на каждое
  изменение.
- `xp:` разбиралось как шкала; «нормально» не очищало статусы; `~occupation:`
  не понимался; «Key» становился обычным событием; U+FE0F прилипал к имени
  предмета; «15.03.1990» читалось как 15-й год; `agenda:|текст` сохранял `|`.
- Удаление плана по `agenda-:` было безвозвратным (не откатывалось свайпом).
- Пары «место → описание» из одного ответа не сохранялись (оставалась последняя).
- Китайские строки в русском выводе (дни недели, метки времени вспоминания,
  заголовки полного текста) — всё по-русски.
- Замок таблицы задним числом отсекал уже записанные ячейки.

## Ограничения
